# バックエンド設計

## このドキュメントについて

- 本ドキュメントは**設計・方針の整理用**です。実装は別タスクとして行う。
- 第一フェーズ（メール送信）・第二フェーズ（microCMS お知らせ）の構成とやることをここに集約し、実装時に参照する。

---

## 基本方針

バックエンドサーバーは持たない。Vercel の API Route（サーバーレス関数）と外部サービスの組み合わせで完結させる。

---

## フェーズ構成

| フェーズ | 内容 | 追加するもの |
|----------|------|-------------|
| **第一フェーズ** | お問い合わせメール送信（管理者宛のみ） | API Route 1本 + Nodemailer + ロリポップSMTP |
| **第二フェーズ** | お知らせ（microCMS）＋ 送信完了メール（ユーザー宛確認メール） | microCMS + ISR、お問い合わせの確認メール送信 |

---

## 第一フェーズ：お問い合わせメール送信

### 構成

```
フォーム送信 → /api/contact (API Route) → Nodemailer (SMTP) → info@kitauralakeside.com
```

### やること

| 項目 | 内容 |
|------|------|
| **ファイル** | `app/api/contact/route.ts` |
| **処理** | POST でフォーム内容を受け取り、メール本文に整形して送信 |
| **送信方法** | Nodemailer + ロリポップSMTP |
| **環境変数** | `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS`（送信先はコード内で `info@kitauralakeside.com` 固定） |

### 第一フェーズの範囲（やらないこと）

- **送信先は info@kitauralakeside.com への1通のみ**。ユーザーが入力したメールアドレス宛の**送信完了メール（確認メール）は実装しない**。送信完了メールは第二フェーズで実装する。

---

## 第二フェーズ：お知らせ（microCMS）＋ 送信完了メール

### 第二フェーズで追加するもの

- **お知らせを microCMS から入稿**（既存の設計どおり）
- **お問い合わせの送信完了メール（確認メール）**：フォーム送信時に、ユーザーが入力したメールアドレス宛に「お問い合わせを受け付けました」旨のメールを送る。メールアドレス誤記による機会損失を減らす目的。

---

## 第二フェーズ（1）：お知らせを microCMS で管理

### 構成

```
microCMS（入稿画面）
    │
    │ API（GET）
    ▼
Next.js（ビルド時 or ISR で取得）
    │
    ▼
お知らせ一覧・詳細ページに表示
```

### microCMS 側の設計

**API名**: `news`（お知らせ）

| フィールド | フィールドID | 種類 | 必須 |
|-----------|------------|------|------|
| タイトル | `title` | テキスト | ○ |
| 公開日 | `publishedAt` | 日時 | ○ |
| 本文 | `body` | リッチエディタ | ○ |
| カテゴリ | `category` | セレクト（お知らせ / メディア掲載 / 料金改定 など） | - |

### Next.js 側の設計

| 項目 | 内容 |
|------|------|
| **取得方法** | ISR（`revalidate: 60` 程度）でビルド後もキャッシュを定期更新 |
| **一覧** | 既存の `components/news.tsx` のデータソースを microCMS API に差し替え |
| **詳細ページ** | `app/news/[slug]/page.tsx`（必要に応じて追加） |
| **環境変数** | `MICROCMS_SERVICE_DOMAIN` / `MICROCMS_API_KEY` |
| **ライブラリ** | `microcms-js-sdk`（公式SDK、1つ追加するだけ） |

### 第二フェーズで変わるファイル（想定）

```
app/
  news/
    [slug]/
      page.tsx          ← 詳細ページ（新規）
lib/
  microcms.ts           ← SDK初期化 + 型定義（新規）
components/
  news.tsx              ← データソースをハードコード → microCMS に差し替え
```

### 現在のお知らせ（ハードコード）との互換

- 第一フェーズでは `news.tsx` のハードコードのまま運用。
- 第二フェーズで microCMS に移行する際、**既存のお知らせ内容を microCMS に入稿し直す**だけ。
- コンポーネントの見た目・レイアウトは変更不要（データの取得元だけ変わる）。

---

## 第二フェーズ（2）：送信完了メール（確認メール）

- お問い合わせフォーム送信時、**管理者宛（info@）への送信**に加え、**ユーザーが入力したメールアドレス宛に確認メールを1通送る**。
- 内容例：「お問い合わせありがとうございます。内容を確認のうえ、担当者からご連絡いたします。」など。
- 実装方針：`/api/contact` 内で、Resend（または Nodemailer）を使って同一リクエスト内で「管理者宛」と「ユーザー宛」の2通を送る、またはユーザー宛のみ追加送信する。

           │                 │

           ▼                 ▼
   ┌──────────────┐  ┌──────────────────┐
   │  microCMS    │  │  SMTP（ロリポップ） │

                   info@kitauralakeside.com
                   （MXレコードはロリポップ維持）

## やらなくていいこと（過剰設計の回避）

| よくある提案 | このサイトで不要な理由 |
|---|---|
| **DB（Supabase 等）** | お知らせは microCMS で管理。他に動的データなし |
| **認証（NextAuth 等）** | 管理画面は microCMS の管理画面を使う |
| **予約管理API** | LINE + なっぷで完結 |
| **独自CMS** | microCMS で十分 |

## 環境変数まとめ

| 変数名 | フェーズ | 用途 |
|--------|---------|------|
| `SMTP_HOST` | 第一 | ロリポップ SMTP ホスト（例: smtp.lolipop.jp） |
| `SMTP_PORT` | 第一 | ポート（例: 465） |
| `SMTP_SECURE` | 第一 | true / false（465 のとき true） |
| `SMTP_USER` | 第一 | メールアカウント（例: info@kitauralakeside.com） |
| `SMTP_PASS` | 第一 | メールアカウントのパスワード |
| （送信先） | 第一 | コード内で `info@kitauralakeside.com` 固定（環境変数なし） |
| `MICROCMS_SERVICE_DOMAIN` | 第二 | microCMS のサービスドメイン |
| `MICROCMS_API_KEY` | 第二 | microCMS の API キー |
